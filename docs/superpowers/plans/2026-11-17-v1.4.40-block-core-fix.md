# v1.4.40：#934 屏蔽失效——核心侧修复（MyInterfaceAddress 返回 TUN 地址）

## 根因（已由真机日志证实，2026-11-17）
- 屏蔽模式下全部流量进 TUN，靠核心的 user_id 规则拦。但核心从不查连接属于哪个 App：几十条 TUN 连接里一次都没有 "failed to search process" / "found user id"。
- 断点在 sing-box `Router.isLocalSource`（route/process_cache.go:77）：先看 `MyInterfaceAddress()`，再看 InterfaceFinder 的接口列表。NekoBox 的 `boxPlatformInterfaceWrapper.MyInterfaceAddress()` 直接返回 nil；InterfaceFinder 是个空 stub（interface_monitor.go 的 `MyInterfaces()` 返回 nil），所以 TUN 源地址 172.19.0.1 不被认作本地，`searchProcessInfo` 静默提前返回，ProcessInfo 恒为 nil，user_id 规则永远匹配不上。
- 绕过/代理模式不受影响：它们走安卓 VpnService 的 allow/disallow，系统在内核层按 UID 分流，核心不用认 App。

## 修法（Go 侧，libcore）
- `libcore/platform_box.go`：给 `boxPlatformInterfaceWrapper` 加 `tunAddresses`（RWMutex 保护）。
- `OpenInterface` 里拿到 TUN fd 后，把 `options.Inet4Address` / `options.Inet6Address`（各 prefix 的 Addr，如 172.19.0.1）记下来。（注意：sing-tun 的 Options 没有 `Address` 字段，是拆开的 Inet4/Inet6Address，2026-11-17 首次重编时编译报错纠正过。）
- `MyInterfaceAddress()` 返回记下的地址（无 TUN 时返回 nil，与原来一致，无回归）。
- 其余链路不动：`FindConnectionOwner` 本来就走 `intfBox.FindConnectionOwner`（Android Q+ API），一旦 isLocalSource 放行，查找就会跑起来，返回 UID（如 Google 的 10440），block 规则随即匹配。
