# KoNeko v1.4.33 Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship KoNeko v1.4.33 with six verified upstream bug fixes (subscription update deadlock, wake reset, About crash race, TUIC password parsing, bypass route gaps, connection-test lifecycle) and document why XHTTP support is blocked.

**Architecture:** Kotlin-only fixes in the app layer, no libcore rebuild, no database migration. Each fix gets a file-parsing regression test in `app/src/test/java/io/nekohasekai/sagernet/ui/` (repo convention: unit tests assert on source content, they never touch Android APIs). Full suite must stay green; release build verified by aapt2 + apksigner.

**Tech Stack:** Kotlin, Gradle 8.10.2, JDK 17, sing-box core 1.14.4 (unchanged), Room DB v8 (unchanged).

**Spec:** Upstream issues #1181, #1142, #1192, #1090, #963, #954/#1120/#1141/#918, plus the XHTTP gap (#1169). All six fixes were verified against the VM tree before planning; XHTTP was verified NOT implementable (see Task 7).

## Global Constraints

- Canonical tree is `/data/workspace/koneko/nekobox-tmp` on the InstaBox VM only; never touch the sandbox copy at `~/workspace/tools/nekobox-tmp`.
- Version: `nb4a.properties` VERSION_NAME=1.4.33, VERSION_CODE=77 (versionCode=385), PRE_VERSION_NAME=pre-1.4.32.
- No GitHub push. No keystore copies elsewhere.
- No database migration: bean serialization format changes are out of scope (XHTTP needs one, which is part of why it is blocked).
- Build env: `source /data/workspace/koneko/env.sh`; `gradle --stop` before the release build; release command `nkmr_minify=0 gradle app:assembleOssRelease --max-workers=1 --console=plain`.
- Tests run with `gradle app:testOssDebugUnitTest --max-workers=1 --console=plain`.

## Review Focus

- Subscription update with VPN off must not get slower than today (direct attempt must fail fast when nothing is wrong, proxy fallback only when the service is connected).
- A wake-reset must not fire twice per unlock in a way the user can see (double reset is harmless, double toast is not; there is no toast here, only Libcore.resetAllConnections).
- A cancelled batch test must never leave DataStore.runningTest true (that blocks every later test).
- A TUIC node imported from a password-only link must still produce a config the core accepts (uuid must never be empty in emitted JSON).
- Emitting a transport type the core does not know breaks the whole service start, not just one node (never emit `xhttp`).

### Task 7: XHTTP support — BLOCKED, no code change

**Evidence (verified 2026-11-16):** sing-box 1.14.4 has no XHTTP transport in any version. `option/v2ray_transport.go` switches on exactly five types (`http`, `ws`, `quic`, `grpc`, `httpupgrade`); a case-insensitive grep for `xhttp` over all 1170 Go files in `/data/workspace/koneko/sing-box` returns zero hits; `constant/v2ray.go` defines only the same five constants. Independent sources confirm: "XHTTP / SplitHTTP — sing-box: never, any version" and "sing-box has no xhttp transport in any version. Fail loudly; never downgrade to ws."

**Consequence:** emitting `"transport": {"type": "xhttp", ...}` would make `box.New` fail with `unknown transport type: xhttp` and the whole VPN service would fail to start, not just that node. The premise "core 1.14.4 already supports it, only the GUI is missing" is wrong.

**Decision:** do not implement parsing, emission, or the UI option in this release. Do not touch `V2RayFmt.kt`, `StandardV2RayBean.java`, or `StandardV2RaySettingsActivity.kt` for XHTTP. Record the finding in the delivery report. Future path if ever wanted: switch to a forked core with XHTTP (e.g. sing-box-lx, `with_xhttp` build tag) — a core project on the scale of the 1.14.4 upgrade, not a GUI patch. Note: today a `type=xhttp` link parses to a bean with `type="xhttp"` and no transport, i.e. it silently degrades to plain TCP; that pre-existing behavior is left untouched in this release.

- [ ] **Step 1: No code change. Confirm the finding is recorded in the delivery report.**
