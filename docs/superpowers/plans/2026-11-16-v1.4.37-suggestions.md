## Review Focus

- wireguard:// 链接的私钥是 base64，可能含 `/`（userinfo 里非法字符）：HttpUrl 若拒收，必须有手动解析 userinfo 的兜底；测试必须用含 `/` 的私钥钉住这一行为。
- 屏蔽模式下被屏蔽的 App 必须仍进 TUN（否则 sing-box 看不到它的流量、拦不住）：VpnService 在屏蔽模式不得对它调 `addDisallowedApplication`。
- 屏蔽规则必须优先于用户自定义路由规则，否则用户规则会把被屏蔽 App 的流量先放走：路由规则与 DNS 规则均插到列表最前。
- 旧版 Kryo 数据（v1.4.36 及之前保存的节点）读新字段时不能崩：新字段只在 `version >= N` 时读，缺失时靠 `initializeDefaultValues()`。
- 剪贴板导出/导入格式改了三行：旧版导出的两行（`true|false` + 节点列表）仍须能导入。

## Task 2: #1035 — 新增 wireguard:// 链接解析（含 presharedkey）

**Files:**
- Modify: `app/src/main/java/io/nekohasekai/sagernet/fmt/wireguard/WireGuardFmt.kt`
- Modify: `app/src/main/java/io/nekohasekai/sagernet/ktx/Formats.kt`

**Interfaces:**
- Consumes: `WireGuardBean`（已有 `peerPreSharedKey` 字段）、`okhttp3.HttpUrl`（其它解析器同款）。
- Produces: `fun parseWireGuardLink(url: String): WireGuardBean`。

链接格式（本任务定稿，测试钉住）：`wireguard://<privateKey>@<host>:<port>/?publickey=<pk>&presharedkey=<psk>&address=<ip1,ip2>&mtu=<n>&reserved=<b64>&keepalive=<s>#<name>`；私钥也接受 `privatekey` 查询参数；`keepalive` 也接受 `persistentkeepalive`。

- [ ] **Step 1: 在 `WireGuardFmt.kt` 写 `parseWireGuardLink(url: String): WireGuardBean`**：**已验证（okhttp 5.0.0-alpha.3，沙箱 JVM 实测）：HttpUrl 会把 userinfo 里的 `/` 当路径分隔符静默解析错（`wireguard://abc/def…@host` 被当成 host=`abc`、username 为空），不能直接用它解析整条链接**。做法：先 `removePrefix("wireguard://")`，在最后一个 `@` 处（`lastIndexOf('@')`）手动切出 userinfo（私钥；只做 %XX 百分号解码，`+` 保持原样——`URLDecoder` 会把 `+` 变空格、会损坏 base64 私钥，故写一个 10 行左右的 `percentDecodeAscii` 本地函数，用字节缓冲 + UTF-8 还原），剩余部分拼成 `https://…` 再用 HttpUrl 解析 host/port/query/fragment；`privateKey` = 解码后的 userinfo，为空时取 `privatekey` 参数，再空则 `error`；`serverAddress` = `link.host`，`serverPort` = `link.port`（<=0 则 `error`）；`publickey` 参数必填，缺失则 `error`；`presharedkey` → `peerPreSharedKey`（可选）；`address` 参数按逗号切分后用 `\n` 连接进 `localAddress`；`mtu` → `toIntOrNull()`；`reserved` 原样；`keepalive` / `persistentkeepalive` → `toIntOrNull()` 进 `persistentKeepalive`（Task 6 的字段）；`fragment` → `name`。
- [ ] **Step 2: `Formats.kt` 的 `parseLink` 加分支**：`else if (startsWith("wireguard://"))`，`runCatching { entities.add(parseWireGuardLink(this)) }.onFailure { Logs.w(it) }`（与其它分支同款），并加 import。
- [ ] **Step 3: `AndroidManifest.xml` 的 profile_import intent-filter 加一行**：`<data android:scheme="wireguard" />`（与现有 `ss` / `vmess` 行并列）。
- [ ] **Step 4: 写真行为单测 `app/src/test/java/io/nekohasekai/sagernet/ui/WireGuardLinkParseTest.kt`**（3 例：私钥含 `/` 与 `+` 的完整链接逐字段断言；无 `presharedkey` 时为空白；缺 `publickey` 时抛错），跑通则保留，跑不通（Android stub 拦类加载）则删除、只留文件解析测试与已做的 HttpUrl 验证。
- [ ] **Step 5: 运行 `Fixes1437Test` 的 #1035 两例**（+ `WireGuardLinkParseTest` 若保留），确认变绿；其余测试仍按预期红/绿。
