# Chain Proxy Shows Node Names (#1212) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Chain profiles in the profile list show the names of the nodes in the chain on the card's second line, so the user can see which nodes are used (issue #1212, 免流 use case).

**Architecture:** Resolve chain node names in the list UI layer (ConfigurationAdapter) from the already-loaded in-memory profile map, cache one string per chain ID, and use the cached string in binding and search. No model-layer change: overriding ChainBean.displayAddress() would create a fmt→database circular dependency (ProxyEntity already imports ChainBean) and would do a Room query per call. Cache is rebuilt whenever any profile in the group changes, so a node rename/delete refreshes every chain that references it.

**Tech Stack:** Kotlin, Android RecyclerView, JUnit (existing file-parsing style + pure-function tests).

**Spec:** GitHub issue #1212 (MatsuriDayo/NekoBoxForAndroid) — "链式代理显示所选用节点名称" (chain proxy displays the selected node names).

## Global Constraints

- Version: v1.4.44, versionCode 440 (nb4a.properties: VERSION_NAME=1.4.44, VERSION_CODE=88, PRE_VERSION_NAME=pre-1.4.43).
- Release build MUST use `nkmr_minify=0` (Helpers.kt:91; R8 accident in v1.4.40).
- Build before release: `gradle --stop` first (version metadata is read once per Daemon).
- All unit tests must pass (152 baseline in v1.4.43 + new tests).
- Signature unchanged (same release keystore); APK must be directly installable over v1.4.43.
- Display separator is " → " (U+2192 with spaces).
- Deleted / cross-group node IDs are skipped in the joined string (not shown as raw IDs).

## Review Focus

- Chain whose nodes were all deleted: joined string is empty, card shows no address line (same as today).
- Chain containing a cross-group node: that node is not in the current group's in-memory map, so it is skipped like a deleted node (one-time DB lookup for cross-group nodes is out of scope).
- Node renamed after the chain was cached: cache is rebuilt on ANY profile update in the group, so the chain line picks up the new name without a list reload.
- Long node names / many nodes: the address line is truncated at 30 chars when traffic is shown (existing behavior at binding); the full string is still used for search matching.
- Chain with a custom name: node names still show on the second line (the "no name → hide address" gate is bypassed for chains).
